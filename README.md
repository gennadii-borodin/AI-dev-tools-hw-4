# AI-ассистент QA-инженера

Инструмент автоматизации QA на базе LangChain-агентов для управления функциональными требованиями и тест-кейсами системы электронной коммерции.

## Обзор

Проект реализует QA Lead-агента (персона с опытом более 5 лет), работающего на базе LLM через OpenRouter API. Агент умеет работать с функциональными требованиями и тестовыми сценариями, хранящимися в CSV-файлах, для решения QA-задач, таких как создание тест-планов для проверки исправления дефектов.

## Структура проекта

```
AI-dev-tools-hw-4/
├── api/
│   ├── crud_requirements.py   # CRUD-инструменты для функциональных требований
│   └── crud_tests.py          # CRUD-инструменты для тест-кейсов
├── data/
│   └── requirements/
│       └── functional_requirements.csv  # 50 функциональных требований (RU)
├── tests/
│   ├── test_checklist.csv      # Тест-кейсы на английском (250 тестов, 5 на требование)
│   └── test_checklist_ru.csv   # Тест-кейсы на русском (250 тестов, 5 на требование)
├── lang_chain.py               # Точка входа с LangChain-агентом
├── requirements.txt            # Python-зависимости
├── .env                        # Переменные окружения (не отслеживаются)
└── .gitignore
```

## Возможности

- **LangChain-агент** — QA-ассистент на базе LLM с возможностью вызова инструментов
- **Управление требованиями** — полный CRUD для функциональных требований (получение, добавление, обновление, удаление)
- **Управление тест-кейсами** — полный CRUD для тестовых сценариев (получение, добавление, обновление, удаление)
- **Двуязычная поддержка** — тест-чеклисты на английском и русском языках
- **Хранение в CSV** — простое файловое хранение данных на базе pandas

## Покрытие функциональных требований

Проект включает 50 функциональных требований для системы электронной коммерции:

| Область | Требования |
|---------|-----------|
| Управление пользователями | Регистрация, Авторизация, Восстановление пароля |
| Каталог | Просмотр, Поиск, Фильтрация по категории, Сортировка по цене |
| Корзина | Добавление товаров, Просмотр корзины, Удаление товаров, Изменение количества |
| Оформление заказа | Размещение заказа, Оплата, Выбор доставки |
| Профиль пользователя | Просмотр/редактирование профиля, История заказов |
| Уведомления | Email-уведомления, Обновления статуса заказа |
| Отзывы и рейтинги | Отзывы о товарах, Система рейтингов |
| Список желаний | Добавление/удаление из списка желаний, Просмотр списка |
| Акции и промокоды | Промокоды, Скидки, Рекламные баннеры |
| Поддержка | FAQ, Связь с поддержкой, Запросы на возврат |

Каждое требование сопровождается 5 тест-кейсами (позитивные и негативные сценарии).

## Технологический стек

- **Python** — основной язык
- **LangChain Core** — фреймворк агентов и определение инструментов
- **LangChain OpenRouter** — интеграция с LLM через OpenRouter API
- **LangGraph** — оркестрация агентов
- **Pandas** — работа с CSV-данными
- **OpenRouter** — мульти-модельный LLM-шлюз

## Установка

1. Создайте виртуальное окружение:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate   # Windows
   source .venv/bin/activate  # Linux/macOS
   ```

2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

3. Создайте файл `.env` с вашими учётными данными:
   ```env
   OPENROUTER_MODEL_NAME=название-модели
   OPENROUTER_API_KEY=ваш-api-ключ
   ```

## Использование

Запустите основной скрипт для запуска QA-агента:

```bash
python lang_chain.py
```

Агент предварительно настроен на сценарий:
- **Дефект**: «Удаление товара из корзины не обновляет стоимость всей корзины»
- **Задача**: Создать тест-план для проверки исправления этого дефекта
- **Ресурсы**: Используются существующие требования и тестовые сценарии

### Доступные инструменты агента

| Инструмент | Описание |
|------------|----------|
| `get_all_requirements` | Возвращает список всех функциональных требований |
| `get_requirement_by_id` | Получает требование по его ID |
| `add_requirement` | Добавляет новое требование |
| `update_requirement` | Обновляет существующее требование |
| `delete_requirement` | Удаляет требование по ID |
| `get_all_tests` | Возвращает список всех тест-кейсов |
| `get_test_by_id` | Получает тест-кейс по его ID |
| `add_test` | Добавляет новый тест-кейс |
| `update_test` | Обновляет существующий тест-кейс |
| `delete_test` | Удаляет тест-кейс по ID |

## Формат данных

### Требования (`functional_requirements.csv`)

| Колонка | Описание |
|---------|----------|
| ID | Уникальный идентификатор требования |
| Requirement | Описание требования на русском языке |

### Тест-кейсы (`test_checklist_ru.csv`)

| Колонка | Описание |
|---------|----------|
| Requirement ID | ID связанного требования |
| Requirement | Описание требования |
| Test Case ID | Уникальный идентификатор тест-кейса (например, TC001.1) |
| Test Case Description | Описание тестового сценария |
| Expected Result | Ожидаемый результат |
